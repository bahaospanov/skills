- **traffic-light**: works on GitLab as on GitHub. The forge comes from `origin`: a host named github (github.com or Enterprise) is read with `gh`, a host named gitlab (gitlab.com or self-hosted), or the one `GITLAB_URL` names, through GitLab's REST API. An MR is judged as a PR is: open is yellow ("waiting on MR"), closed or merged elsewhere red, merged green once the newest pipeline of the commit it landed passed on the target branch (the source head for a fast-forward merge), with a pipeline cancelled by a newer push settled by that one, and with no pipeline once cleanup removed its branch. A `glab mr` command or a `merge_requests` API call names the MR to follow, a listing none; a commit pushed straight to an integration branch is judged by its GitLab pipeline. GitLab is read with `GITLAB_TOKEN` (`GITLAB_URL` for another API host) from the environment, else from an env file opted into with `git config traffic-light.envFile <path>`, read and never run, else with a signed-in `glab`; a token goes only to its own host, in a header. A forge it cannot read, an unknown host or a GitLab with no credentials, is red with "can't read …", never green.
